# 架构方案

## 技术栈

- 纯HTML/CSS/JavaScript，无外部框架或库

## 文件设计

### index.html

主页面结构，包含游戏画布、分数显示和重新开始按钮

### style.css

游戏界面样式，包括网格布局、蛇和食物的颜色、按钮样式、游戏结束提示样式

### game.js

游戏核心逻辑，包含蛇移动、食物生成、碰撞检测、分数更新、游戏循环控制等

## 模块设计

### 游戏状态模块

- 职责：管理游戏进行/结束状态、分数、蛇的初始位置、方向队列
- 依赖：无

### 蛇模块

- 职责：管理蛇的身体坐标数组、移动逻辑（方向更新、增加长度）、碰撞检测（自身撞墙）
- 依赖：游戏状态模块

### 食物模块

- 职责：在空白位置随机生成食物，提供食物坐标
- 依赖：游戏状态模块、蛇模块

### 输入处理模块

- 职责：监听键盘方向键事件，更新方向队列（防止反向移动）
- 依赖：游戏状态模块

### 渲染模块

- 职责：根据游戏状态在画布或网格DOM上绘制蛇、食物、分数和游戏结束提示
- 依赖：游戏状态模块、蛇模块、食物模块

### 游戏循环模块

- 职责：使用setInterval或requestAnimationFrame驱动游戏更新：移动蛇、检测碰撞、生成食物、更新分数、触发渲染
- 依赖：游戏状态模块、蛇模块、食物模块、渲染模块、输入处理模块

## 数据流

- 用户按下方向键 → 输入处理模块将方向加入方向队列（队列长度最多2），防止反向移动
- 游戏循环每次 tick 从方向队列取出第一个方向作为当前移动方向，更新蛇头位置
- 蛇模块检查新蛇头是否撞墙或撞自身 → 如果碰撞则游戏结束，状态设为结束，停止循环
- 蛇模块检查新蛇头是否与食物坐标重合 → 若重合则蛇身加长，食物模块生成新食物，分数加1
- 渲染模块根据蛇模块的身体坐标、食物坐标、分数、游戏结束状态更新UI（网格颜色、分数文本、显示/隐藏结束提示）
- 用户点击“重新开始”按钮 → 游戏状态模块重置所有状态（蛇初始位置、分数0、清除方向队列），食物模块重新生成食物，游戏循环重新开始

## 实现注意事项

- 使用固定网格大小20x20，每个单元格在CSS中设置为固定像素（如20px），游戏区域总大小400x400px
- 游戏循环使用 setInterval ，间隔时间 200ms（每秒5格），恒定速度
- 键盘事件监听方向键，阻止默认滚动行为；使用方向队列避免快速按键时丢失输入，每次tick从队列头部取出一个方向
- 蛇的移动：先根据当前方向计算新蛇头坐标，然后将新蛇头插入身体数组头部，若没吃到食物则移除尾部，若吃到则不移除
- 食物生成：遍历所有网格坐标，排除蛇身占据的格子，然后随机选择一个空白格子
- 游戏结束条件：蛇头坐标超出网格边界（0-19）或蛇头坐标与蛇身其他部分坐标重合（不包括新蛇头本身）
- 重新开始：停止当前循环，重置蛇为三段（例如位置(5,5),(4,5),(3,5)），方向设为右，分数置0，生成新食物，重新启动循环
- UI使用画布（canvas）或纯DOM网格（div）均可，建议使用canvas简化绘制
- 所有逻辑写在game.js中，通过window.onload初始化，保持全局函数和变量在模块化命名空间下避免污染
